# 测试用例按上游基线分层并行设计

测试设计不等待全部技术设计完成后一次性生成：PRD 封存后启动业务验收测试，架构封存后启动非功能测试，系统模块封存后启动模块集成测试，数据库和接口完成汇合并分别封存后启动数据完整性与 API 契约测试。各分支只能消费对应的已封存上游基线，提前完成的内容只保存在 `artifact_draft`，不得形成独立测试基线。

所有测试分支就绪后执行统一测试汇合，检查跨层重复、矛盾以及需求与设计覆盖，补齐端到端和回归测试；全部问题解决后以一次 Git Commit 和 Tag 封存唯一当前 `TEST` 基线。测试草稿只能描述测试意图、前置条件、数据、步骤、预期和追踪关系，不能反向补写未经确认的业务规则。

测试用例不设置逐条人工审批，程序校验、Test Reviewer 语义评审和统一测试汇合全部通过后，由 AI PM 自动封存 `TEST` 基线。普通用户可以查看产物并发起变更；测试设计发现未经确认的业务规则时必须升级给项目所有者，这属于业务决策校准而不是测试审批。
