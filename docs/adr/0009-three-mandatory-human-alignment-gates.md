# 设置三个强制人工校准点

平台不能仅在 PM 自认为遇到业务决策时才询问人，否则错误的初始理解可能被自动扩展为完整项目。设计交付设置三个不可自动越过的人工校准点：确认项目简报中的目标和范围、确认需求大纲中的能力与模块地图、批准整合后的 PRD 业务基线；校准点之间由 PM 自动生成和评审，任何阶段仍可因新的业务决策额外升级给人。每次确认必须展示变更、排除项、推导、假设及将解锁的阶段，不能用含义不明的“继续”代替批准。

PRD 业务基线批准后，架构、系统模块、API、数据库和测试设计不设置固定人工审批；Author、确定性校验、Reviewer、PM 返工协调及必要汇合门禁全部通过后自动提交 Git 并封存阶段基线。只有技术工作暴露出业务范围、成本取舍、合规要求、不可逆选择或无法从 PRD 确定的业务规则时，才额外暂停并升级给项目所有者。

存在多个可行方案本身不构成人工升级理由。只要选择不改变已批准业务行为、范围、预算级别、合规要求、可用性承诺或造成需要人承担的不可逆外部依赖，AI 架构角色应选择推荐技术方案、记录备选与取舍并继续；只有技术选择越过这些业务约束时才由 PM 发起人类决策请求。
